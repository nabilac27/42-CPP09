1. Jacobsthal
    Jacobsthal is a mathematical sequence:
    0, 1, 1, 3, 5, 11, 21, 43, ...


In your PmergeMe, we use these boundaries:
    1 → 3 → 5 → 11 → 21 → 43

Think of them as checkpoints.
    They tell the algorithm where to stop when forming groups of pending elements.


The rule is:
    Go to the next checkpoint, then insert backward until you reach the previous checkpoint.


4 Elements:
    b1 → b3 → b2 → b4

Jacobsthal does not sort the values directly.
It only chooses which pending element gets inserted next.
Binary search handles where the element goes.

Why specifically 1, 3, 5, 11, 21?
Because binary search has special comparison thresholds.

Number of elements to search	Maximum comparisons
    1	                        1
    2–3	                        2
    4–7	                        3
    8–15	                    4
    16–31	                    5

Jacobsthal boundaries create insertion groups that exploit these thresholds, 
helping avoid unnecessary comparisons.

numbers generated by
    J(n)=J(n-1)+2J(n-2)

In ordinary language:
    Take the previous Jacobsthal number, then add twice the one before it.

lower_bound()

Binary search finds the first suitable position in that prefix.
    binary search find with lower bound between actual value and actual partner's value 

std::lower_bound() searches for the pending value, 
    but only within the main chain 
        from the beginning 
            up to (excluding) its partner's position.


partnerPosition = std::find(mainChain.begin(), mainChain.end(), partnerValue);

position = std::lower_bound(mainChain.begin(), partnerPosition, currentValue);

In short: lower_bound(begin, partnerPosition, pendingValue) searches 
from the beginning up to the partner, looking for the correct sorted position of the pending value.
