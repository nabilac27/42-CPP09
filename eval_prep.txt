why std::list
- RPN needs LIFO-style operations. 
- I use the back of std::list like the top of a stack. 
- push_back() adds an operand
- back() accesses the last operand
- and pop_back() removes it
- I also use a different container from Ex00 as required.

push_back() → add operand
back()      → access last operand
pop_back()  → remove last operand

std::list is an STL container that stores elements in a doubly linked list.
Unlike std::vector, its elements are not stored next to each other in memory.

std::list is a doubly linked list. 
Each element is stored in a separate node containing the value and pointers to the previous and next nodes. 
Unlike vector, its elements are not contiguous in memory. I use it in RPN as a LIFO stack with push_back(), back(), and pop_back().

Ford-Johnson uses pairs where:
\[
b_i \leq a_i
\]

When inserting b_i, we only need to search before its partner a_i.
For example:
Main chain:  2  5  8  12  20
Pending:     7
Partner:     12

Search:      2  5  8
Do not search: 12  20
